## 🎯 Motivation

With the growing availability of recorded lectures and online learning resources, students often spend significant time searching through lengthy videos to locate a specific concept, explanation, or discussion. Traditional video platforms provide only basic navigation tools, making knowledge retrieval inefficient and time-consuming. This project was developed to bridge that gap by transforming educational content into an intelligent, searchable knowledge base that allows users to interact with their learning materials conversationally.

---

## 💡Solution

The proposed system leverages Retrieval-Augmented Generation (RAG) to provide answers grounded in course content. Lecture videos are first converted into audio and transcribed into text. The transcripts are divided into meaningful chunks and transformed into vector embeddings for semantic search. When a user submits a query, the system retrieves the most relevant content and supplies it as context to a Large Language Model (LLM), enabling accurate and context-aware responses based on the uploaded material rather than relying solely on the model's pre-trained knowledge.

---


# Begin the project = (Installation & Usage)

This project follows a multi-stage Retrieval-Augmented Generation (RAG) pipeline. Each stage depends on the output generated by the previous stage, so it is important to execute the steps in the specified order.

---

## Important Notes

- Large files such as videos, audio recordings, generated JSON files, and embeddings are intentionally excluded from this repository.
- These files can be regenerated by running the complete pipeline on your own dataset.
- Ensure all required directories are created before execution.
- Verify that the necessary Python packages and AI models are installed.

# Step 1: Add Lecture Videos

Place all source lecture videos inside the `videos/` directory.

Example:

```text
videos/
├── lecture_1.mp4
├── lecture_2.mp4
└── lecture_3.mp4
```

These videos serve as the knowledge source for the RAG system.

---

# Step 2: Extract Audio from Videos

Run:

```bash
python video_to_mp3.py
```

Purpose:

- Converts video files into audio format.
- Generates `.mp3` files for transcription.

Output:

```text
audio/
├── lecture_1.mp3
├── lecture_2.mp3
└── lecture_3.mp3
```

---

# Step 3: Generate Timestamped Transcripts

Run:

```bash
python mp3_to_json.py
```

Purpose:

- Uses Whisper to transcribe audio.
- Splits transcripts into timestamped chunks.
- Saves structured data as JSON.

Output:

```json
{
  "timestamp": "00:15:20",
  "text": "Bias variance tradeoff refers to..."
}
```

Generated Files:

```text
json_files/
├── lecture_1.json
├── lecture_2.json
└── lecture_3.json
```

---

# Step 4: Generate Embeddings

Run:

```bash
python preprocess_json.py
```

Purpose:

- Reads transcript chunks from JSON files.
- Generates semantic embeddings using BGE-M3.
- Stores embeddings for efficient retrieval.

Output:

```text
embeddings.joblib
```

This file acts as the local vector knowledge base.

---

# Step 5: Query the Knowledge Base

Run:

```bash
python process_query.py
```

Purpose:

- Loads stored embeddings into memory.
- Accepts user questions.
- Retrieves the most relevant transcript chunks.
- Sends retrieved context to the LLM.
- Generates a context-aware response.

Example:

### User Query

```text
What is the Bias-Variance Tradeoff? //{let it is a doubt from ml course topic }
```

### Retrieved Context

```text
Lecture 5 | Timestamp: 22:14
```

### Generated Response

```text
The Bias-Variance Tradeoff describes the balance between
underfitting and overfitting in machine learning models...
```

---

#  How Retrieval-Augmented Generation Works

1. User submits a question.
2. The query is converted into an embedding.
3. Similar transcript chunks are retrieved.
4. Relevant context is selected.
5. Context is passed to Llama 3.2 via Ollama.
6. The model generates a grounded answer.

Unlike a standard chatbot, responses are generated using information retrieved from the uploaded course content.
